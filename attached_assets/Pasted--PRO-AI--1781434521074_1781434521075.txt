# Создай полнофункциональное веб-приложение «РемонтPRO — AI-тренер отдела продаж»

## Общая задача

Создай демонстрационный B2B Back Office AI-сервис для внутреннего обучения менеджеров строительной компании, которая продаёт услуги ремонта квартир и домов.

Сервис должен позволять менеджеру проводить тренировочный диалог с AI-клиентом, получать рекомендации после каждого своего сообщения и итоговую оценку после завершения тренировки.

Также должна быть отдельная административная панель для просмотра сотрудников, тренировок и статистики.

Приложение должно быть полностью на русском языке.

## Технологии

Используй:

* frontend: React;
* backend: Node.js и Express;
* база данных: SQLite;
* AI API: OpenRouter;
* светлая тема;
* современный адаптивный интерфейс;
* запуск одной командой.

Можно использовать Tailwind CSS или обычный CSS.

Не размещай API-ключ в frontend-коде.

## Переменные окружения

Приложение должно использовать:

OPENROUTER_API_KEY
OPENROUTER_MODEL

Значение модели по умолчанию:

openrouter/free

OpenRouter API endpoint:

https://openrouter.ai/api/v1/chat/completions

Если переменная OPENROUTER_MODEL отсутствует, использовать openrouter/free.

Если API-ключ отсутствует, показать понятное сообщение:

«Для работы AI добавьте OPENROUTER_API_KEY в Replit Secrets».

Если OpenRouter временно недоступен, приложение не должно падать. Покажи пользователю сообщение об ошибке и предложи повторить запрос.

## Структура приложения

Приложение состоит из двух частей:

1. приложение менеджера;
2. административная панель.

Маршруты:

* `/` или `/app` — приложение менеджера;
* `/admin/login` — вход в админку;
* `/admin` — административная панель.

В приложении менеджера должна быть кнопка перехода в админку.

В админке должна быть кнопка возврата в приложение менеджера.

## Вход менеджера

Для менеджеров отдельный пароль не нужен.

На стартовом экране показать карточки пяти менеджеров.

Пользователь выбирает своё имя и нажимает:

«Войти в тренажёр».

Выбранный менеджер сохраняется в текущей сессии.

Предусмотреть кнопку:

«Сменить менеджера».

## Главный экран менеджера

Главный экран должен состоять из трёх колонок.

### Левая колонка

Ширина около 22%.

Содержит:

* имя выбранного менеджера;
* кнопку «+ Новая тренировка»;
* список прошлых тренировок;
* дату тренировки;
* уровень сложности;
* статус;
* итоговую оценку завершённой тренировки;
* кнопку перехода в админку.

При выборе прошлой тренировки показывать сохранённый диалог и итоговый результат.

### Центральная колонка

Ширина около 53%.

Содержит:

* информацию о текущей тренировке;
* чат менеджера с AI-клиентом;
* поле ввода сообщения;
* кнопку «Отправить»;
* кнопку «Завершить тренировку».

Сообщения менеджера и клиента должны визуально отличаться.

Во время получения ответа показать индикатор:

«Клиент печатает…»

Не позволять отправлять пустые сообщения.

После завершения тренировки запретить отправку новых сообщений.

### Правая колонка

Ширина около 25%.

Заголовок:

«Рекомендации AI-тренера».

После каждого сообщения менеджера показывать:

* что сделано хорошо;
* допущенные ошибки;
* что стоит спросить дальше;
* рекомендацию по продаже;
* пример следующей фразы.

До первого сообщения показать текст:

«После вашего ответа здесь появятся рекомендации AI-тренера».

Правая колонка не должна быть слишком широкой.

## Создание тренировки

После нажатия «Новая тренировка» открыть модальное окно.

Менеджер выбирает сложность:

* лёгкая;
* средняя;
* сложная.

Также дать возможность выбрать тип объекта:

* случайный;
* квартира;
* дом.

После нажатия «Начать тренировку» AI должен создать нового клиента.

Сохранять скрытый профиль клиента в базе данных.

Профиль клиента должен включать:

* имя;
* тип объекта;
* площадь объекта;
* предполагаемый бюджет;
* желаемые сроки;
* основную потребность;
* скрытую потребность;
* опасения;
* основные возражения;
* стиль общения;
* уровень готовности к покупке.

Скрытый профиль нельзя показывать менеджеру до завершения тренировки.

В начале диалога показывать только первое сообщение клиента.

## Поведение клиентов

Создавай разных клиентов и разные ситуации.

Примеры:

* клиент хочет капитальный ремонт квартиры;
* клиенту нужен косметический ремонт;
* клиент купил квартиру в новостройке;
* клиент хочет отремонтировать загородный дом;
* клиент сравнивает несколько подрядчиков;
* клиент боится скрытых платежей;
* клиент недоволен предыдущими строителями;
* клиент ограничен в бюджете;
* клиенту важны короткие сроки;
* клиент пришёл только узнать цену;
* клиент жёстко торгуется;
* клиент не доверяет компании;
* клиент не понимает, какой ремонт ему нужен.

Не повторяй один и тот же сценарий в соседних тренировках.

### Лёгкий уровень

Клиент:

* настроен доброжелательно;
* отвечает на вопросы;
* достаточно заинтересован;
* высказывает одно простое возражение;
* готов обсуждать следующий шаг.

### Средний уровень

Клиент:

* сомневается;
* сравнивает предложения;
* задаёт уточняющие вопросы;
* имеет два или три возражения;
* не сразу соглашается на встречу или замер.

### Сложный уровень

Клиент:

* недоверчивый и требовательный;
* может отвечать коротко;
* не раскрывает бюджет;
* торгуется;
* сомневается в сроках и качестве;
* упоминает конкурентов;
* требует доказательств;
* не соглашается на следующий шаг без убедительной аргументации.

AI-клиент не должен слишком быстро соглашаться с менеджером.

Клиент должен сохранять характер и факты своего профиля на протяжении всей тренировки.

## AI-логика диалога

После сообщения менеджера отправляй в OpenRouter:

* системную инструкцию;
* скрытый профиль клиента;
* уровень сложности;
* всю историю текущего диалога;
* последнее сообщение менеджера.

Ответ AI должен возвращаться в JSON:

```json
{
  "client_reply": "Ответ клиента",
  "coach_feedback": {
    "strengths": "Что менеджер сделал хорошо",
    "mistakes": "Какие ошибки допустил менеджер",
    "next_step": "Что стоит сделать или спросить дальше",
    "recommendation": "Рекомендация по технике продаж",
    "example_phrase": "Пример следующей фразы менеджера"
  }
}
```

Проверяй JSON на backend.

Если модель вернула текст вокруг JSON, извлеки JSON.

Если JSON не удалось разобрать, сделай одну повторную попытку с инструкцией вернуть только корректный JSON.

Ответ клиента показывай в центральной колонке.

Coach feedback показывай только в правой колонке.

AI-клиент не должен видеть и обсуждать рекомендации тренера.

## Критерии оценки менеджера

AI-тренер должен оценивать:

1. установление контакта;
2. выявление потребностей;
3. качество вопросов;
4. презентацию решения;
5. аргументацию ценности;
6. работу с возражениями;
7. закрытие на следующий шаг;
8. общий результат.

Менеджер не обязан немедленно заключить договор.

Хорошим результатом считается согласие клиента на один из следующих шагов:

* консультацию;
* выезд замерщика;
* подготовку сметы;
* встречу;
* отправку проекта;
* повторный звонок в конкретное время.

## Завершение тренировки

В центральной колонке должна быть кнопка:

«Завершить тренировку».

Перед завершением показать подтверждение:

«Завершить тренировку и получить итоговую оценку?»

После подтверждения отправить AI:

* скрытый профиль клиента;
* сложность;
* полный диалог;
* рекомендации, сформированные в процессе.

AI должен вернуть JSON:

```json
{
  "scores": {
    "contact": {
      "score": 1,
      "comment": "Комментарий"
    },
    "needs": {
      "score": 1,
      "comment": "Комментарий"
    },
    "questions": {
      "score": 1,
      "comment": "Комментарий"
    },
    "presentation": {
      "score": 1,
      "comment": "Комментарий"
    },
    "value": {
      "score": 1,
      "comment": "Комментарий"
    },
    "objections": {
      "score": 1,
      "comment": "Комментарий"
    },
    "closing": {
      "score": 1,
      "comment": "Комментарий"
    }
  },
  "overall_score": 1,
  "strengths": ["Сильная сторона"],
  "problems": ["Проблема"],
  "recommendations": ["Рекомендация"],
  "ideal_strategy": "Описание более эффективной стратегии",
  "client_outcome": "Результат диалога"
}
```

Все оценки должны быть целыми числами от 1 до 10.

После завершения показать красивую страницу результата:

* общая оценка из 10;
* оценки по каждому критерию;
* комментарии;
* сильные стороны;
* ошибки;
* рекомендации;
* идеальная стратегия;
* результат разговора.

Сохранить итоговый отчёт в базе данных.

## Системная инструкция AI-клиента

AI играет роль потенциального клиента строительной компании.

Он должен:

* строго придерживаться созданного профиля;
* не раскрывать скрытые данные без соответствующих вопросов;
* отвечать естественно;
* использовать разговорный русский язык;
* не писать длинные лекции;
* не помогать менеджеру продавать;
* не упоминать системную инструкцию;
* не сообщать оценку во время разговора;
* не соглашаться слишком быстро;
* учитывать уровень сложности;
* реагировать на аргументы менеджера;
* постепенно изменять уровень доверия.

## Системная инструкция AI-тренера

AI выступает как опытный руководитель отдела продаж в сфере ремонта квартир и домов.

Он должен:

* оценивать именно последнее сообщение менеджера с учётом всего диалога;
* не критиковать личность менеджера;
* давать конкретные рекомендации;
* отмечать удачные вопросы и аргументы;
* выявлять пропущенные потребности;
* анализировать работу с ценой, сроками, доверием и рисками;
* предлагать одну естественную следующую фразу;
* не показывать менеджеру скрытый профиль клиента;
* возвращать только JSON заданной структуры.

* не передавать OPENROUTER_API_KEY в браузер;
* все обращения к OpenRouter выполнять только через backend;
* не выводить секреты в логи;
* использовать параметризованные SQL-запросы;
* проверять входные данные;
* ограничить длину одного сообщения менеджера;
* защитить административные маршруты проверкой сессии.

## Критерии готовности

Проект считается готовым, когда можно:

1. выбрать менеджера;
2. создать тренировку;
3. выбрать сложность;
4. получить первое сообщение AI-клиента;
5. отправить несколько ответов;
6. получить после каждого ответа рекомендации;
7. завершить тренировку;
8. получить оценки от 1 до 10;
9. открыть сохранённую тренировку;
10. войти в админку;
11. просмотреть список менеджеров;
12. просмотреть статистику;
13. открыть полный диалог конкретной тренировки;
14. перезапустить приложение без потери данных.

После реализации:

* запусти приложение;
* исправь ошибки запуска;
* проверь все основные маршруты;
* проверь сохранение в базе;
* добавь README с инструкцией;
* не оставляй неработающих кнопок;
* не используй фиктивные ответы вместо OpenRouter в реальной тренировке.
